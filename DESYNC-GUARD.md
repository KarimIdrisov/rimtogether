# RimTogether Guard: защита от десинков

Guard сохраняет сравнение RNG и игрового состояния. Сервер остаётся ретранслятором команд и хранилищем снимков; независимую копию симуляции он не исполняет. Источник восстановления — загрузившийся клиент хоста, который сервер пока не пометил как десинхронизированный. Полностью исключить десинки произвольных модов эта схема не может.

## Что исправлено

| Проблема | Изменение |
|---|---|
| Хост отдельного сервера не отправлял joinpoint: код проверял только LocalServer/Arbiter | Сервер сообщает реальную роль в пакете входа. Подключённый хост публикует снимок; роль из UI не является источником полномочий. |
| Async-продолжения переходили в пул потоков и могли менять коллекции одновременно с серверным тиком | Убран ContinueWith; продолжения возвращаются через SynchronizationContext в очередь серверного цикла. |
| Незавершённый снимок мог частично заменить карты | Пакет сначала полностью разбирается в локальные данные; gzip и его размер проверяются до атомарного присваивания. |
| После зависшего joinpoint повторный вход ждал бесконечно | Через 30 секунд ожидание завершается сохранением старой точки и полного журнала команд. |
| Поздний ответ мог попасть в следующий запрос | Каждый запрос имеет номер, передаваемый в команде и ответе. Просроченный или повторный номер отклоняется. Отправка также привязана к исходному соединению клиента. |
| Отсутствие хоста вызывало обращение к несуществующему HostPlayer | Нет нового снимка без готового источника; десинхронизированный/загружающийся источник не принимается. |
| Первым конфиги сервера мог задать друг | Начальную конфигурацию выделенного сервера предоставляет хост. Ранний вход друга отклоняется до готовности хоста. |
| Длинный журнал команд увеличивал время повторной симуляции | Готовый хост создаёт свежую точку по запросу при входе и десинке. Периодические перезагрузки мира отключены; быстрый TCP-путь сохранён. |
| Перезапуск хоста сбрасывал его счётчик работы, оставляя порог прошлой сессии | Сервер распознаёт сброс счётчика; свежие точки снова доступны после небольшой новой работы. Сетевой таймер на паузе не считается продвижением мира. |
| Для восстановления требовался ручной повторный вход | После отчёта клиент друга делает одну попытку штатного Rejoin по существующему соединению. Быстрый повтор отключает автоматическое восстановление до переподключения. Ручной путь сохраняется. |
| Ошибка необязательных метаданных блокировала отчёт | Основной ZIP сохраняется без ожидания незавершённых задач; ошибки необязательных частей записываются отдельно. Успех сохранения возвращается окну. |
| Фоновый replay мог обращаться к уже заменённой сессии | Метаданные, время и копии коллекций захватываются до фоновой записи; временный файл уникален. |
| Повреждённый gzip внутри корректного JSON считался допустимым checkpoint | При восстановлении проверяется сжатое содержимое; остаётся предыдущая копия. Поддержан также мир без активных карт, например при путешествии каравана. |

Клиент содержит три целевых исправления upstream: [генерация названий квестов, зависящая от языка](https://github.com/rwmt/Multiplayer/commit/c474db632b45d4526715083e983e5d67984f8189), [RNG в проверке посадки на гравкорабль](https://github.com/rwmt/Multiplayer/commit/ea633b8d7c276ca6adc670a22f874d75c78f4548) и [остановка мобилизованного колониста в PawnGotoAction](https://github.com/rwmt/Multiplayer/commit/a481546). Очистка RNG-контекста генератора выполняется также при исключении.

## Как обновиться

Закройте игру и лаунчер у обоих, запустите `RimTogether.Start.exe`. Текущий транспорт Guard использует протокол 5402, поэтому старые клиенты не смешиваются с обновлённой сборкой. Хост проверяет файлы и создаёт новое приглашение; друг вставляет его после обновления. Сохранения Guard 5401 совместимы: RNG-правила и ID команд не менялись. Подробности TCP/UDP: [TRANSFER-PERFORMANCE.md](TRANSFER-PERFORMANCE.md).

Старые данные принимаются только как полный снимок: одинаковые начало/конец секции и пустая история команд. Переигрывать исторический replay старого мода под новыми RNG-правилами небезопасно, поэтому такой импорт отклоняется. Нужно загрузить его старой версией MP и сделать обычное полное MP-сохранение. Для уже существующего серверного checkpoint сначала сохраните копию папки `server/world`; при необходимости перенесите её в backup и выберите свежий полный ZIP. Импорт проверялся также на локальном полном сохранении пользователя; сам файл в репозиторий не входит.

Перед сменой протокола создаётся `checkpoint.before-protocol-<номер>.json`; прежние pre-guard копии сохраняются. Новые checkpoint имеют Guard-тег и протокол, чтобы старый лаунчер не начал молча проигрывать команды другой сборки. Откат программы не означает автоматический откат мира.

Полная точка требует `SaveAndReload()` живого Unity-мира на игровом потоке. Она создаётся при входе и десинке, но больше не по таймеру и не дополнительно после обычного автосейва. Сериализация, проверка и атомарная запись серверного checkpoint выполняются в отдельном потоке над копиями контейнеров готовых сжатых данных и журнала команд. Очередь держит одну запись и только последнее ожидающее состояние; остановка дожидается записи. Ошибка диска выводится в лог, прежние файлы сохраняются.

Флажок у друга управляет автоматической попыткой восстановления; ручной путь сохраняется. Обычный автосейв игры, создание новой точки и загрузка мира при фактическом восстановлении всё ещё могут давать паузу. Пауза после десинка автоматически не снимается. Без свежей точки, например при недоступном хосте, остаётся прежний снимок с журналом: его переигрывание может занять дольше.

## Проверки и границы доказательств

Регрессионные тесты проверяют поздние/неполные/повреждённые снимки, таймаут и повтор запроса, недоступного хоста, запрет публикации от десинхронизированного хоста, перенос продолжений на серверный поток, circuit breaker и восстановление checkpoint. Сетевой тест с двумя UDP-клиентами получает новый снимок от владельца и повторно загружает его без перезапуска сервера. Проверяется также реальный протокол в упакованной клиентской DLL.

Локально проверена загрузка Guard в копии установленного RimWorld 1.6.4633, с отдельной папкой данных и графическим устройством, без ошибок инициализации/привязки патчей. Это проверка запуска мода, а не полноценная игровая сессия. CI использует синтетический мир и не содержит личных сохранений или файлов игры. Длительную игру на двух физических ПК через Radmin и поведение всех сценариев Odyssey нужно проверить в вашей колонии. Первое новое сообщение о десинке и отчёт MpDesyncs будут нужны для дальнейшего точечного исправления.

Новая команда остановки добавлена в конец таблицы с максимальной версией регистрации. В локальном запуске с вашим набором DLC сравнивались таблицы до/после патча: все 734 существовавших ID совпали, новая команда получила ID 734. Остальные изменения ветки upstream dev целиком не переносились.
