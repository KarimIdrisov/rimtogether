RimTogether — общий лаунчер через GitHub

Скачать один раз:
https://github.com/KarimIdrisov/rimtogether/releases/latest/download/RimTogether.Start.exe

Запускайте именно RimTogether.Start.exe. При каждом запуске он получает
последний стабильный релиз из общего репозитория и проверяет SHA256.
Лаунчер, сервер и Multiplayer устанавливаются целиком одной версией.
Git, GitHub-аккаунт и отдельная установка .NET игрокам не нужны.

Хост: включи Radmin, выбери роль «Хост», папку игры, свой ник и Radmin IP.
Выбери начальное MP-сохранение ZIP из MpReplays, проверь обновления,
скопируй приглашение другу и нажми «Запустить и подключиться».
Друг: скачай тот же стартовый EXE по ссылке, укажи свою игру и свой ник,
вставь приглашение хоста, нажми «Запустить и подключиться».
В RimWorld нужно ввести общий пароль из приглашения. Ники должны различаться.

Требуется RimWorld 1.6.4633 с одинаковыми DLC и Prepatcher в Mods у обоих.
Саму игру, DLC и произвольные сторонние моды GitHub не распространяет.
Multiplayer Guard устанавливается из проверенного официального ZIP и
скомпилированного rt-guard1 payload с проверкой хешей DLL. Протокол: 5402.
После перехода на Guard обновитесь ОБА через стартовый EXE и создайте
новое приглашение. Обычный Multiplayer без Guard к этому серверу не подключится.
Подготовка профиля отключает hiteke.steam, ставит Prepatcher первым,
Multiplayer после Core/DLC. Старый мод и конфиги сохраняются в backup.
Контрольная сумма сравнивает DLL игры, порядок активных модов, их XML/DLL.
Остальные активные моды должны быть локально в Mods и совпадать у обоих.

ЗАЩИТА И БЫСТРЫЙ СИНК
Исправления upstream изолируют RNG при названиях квестов и проверке
посадки на гравкорабль, а также синхронизируют остановку бойца при приказе
движения. Трассировка десинков включается после загрузки мира.
Хост первым входит в игру и задаёт серверу начальные конфиги. После этого
может войти друг. Если друг пришёл раньше, нужно повторить вход после хоста.
Включённый «Быстрый синк» обновляет точку мира примерно каждые 90 секунд,
пока мир идёт и хост готов. Создание точки может кратковременно приостановить
игру для перезагрузки; на больших колониях эта цена ещё не измерена.
При десинке друга отчёт записывается и примерно через 5 секунд запускается
одна попытка перезагрузить снимок хоста. Время загрузки зависит от мира и сети.
При повторе в течение 3 минут автоматика отключается до нового соединения,
а кнопка ручного синка остаётся. Хост автоматически не откатывается.
Ожидание новой точки ограничено 30 секундами; при таймауте остаётся прежняя
точка с полным журналом команд. Старый ответ на новый запрос не принимается.
Пауза после десинка сохраняется: продолжать игру можно после восстановления.

ОБНОВЛЕНИЯ
Обычный запуск: проверка релиза -> проверка размера/SHA256 -> установка
в новую папку -> переключение текущей версии -> запуск лаунчера.
Старая версия сохраняется. Если GitHub недоступен, используется проверенная
установленная версия. Для самой первой установки интернет необходим.
Пока игра, сервер или лаунчер запущены, обновление откладывается.
Для перехода на новый релиз закройте игру и лаунчер у обоих и запустите
RimTogether.Start.exe снова. Не запускайте сервер непосредственно из папки.
Новые версии MP меняются только вместе с совместимым сервером в релизе;
случайная Continuous-сборка автоматически не устанавливается.

СЕРВЕР
Работает на ПК хоста, пока открыт его лаунчер. Не круглосуточный облачный.
Слушает Radmin IPv4 хоста и 127.0.0.1, UDP 30502, максимум 2 игрока, пароль.
Если соединения нет, проверь входящий UDP 30502 для RimTogether.Server.exe
и TCP 30502 для ускоренной передачи карты. При недоступном TCP остаётся UDP.
в сети Radmin. Проброс роутера не нужен для виртуального адреса VPN.
Автосохранение серверного состояния — каждые 30 секунд, с предыдущей копией.
При создании joinpoint запись может задерживаться. После аварии возможна
потеря прогресса после последней контрольной точки. Закрытие лаунчера
штатно останавливает сервер. Без игроков мир не тикает.
Начальный ZIP используется только при первом старте; исходный файл не меняется.
Старый ZIP должен быть полным сохранением без истории команд. Исторический
replay нельзя безопасно проигрывать под изменёнными RNG-правилами: загрузите
его старым MP и сделайте обычное полное MP-сохранение. Guard отклоняет
небезопасный импорт, сохраняя исходник. При переходе создаётся
checkpoint.pre-guard.json; старые программы не читают новые Guard-checkpoint.

ЛИЧНЫЕ ДАННЫЕ
%LOCALAPPDATA%\RimTogether — настройки, пароль, приглашение/контрольная сумма,
логи, резервные копии, серверные checkpoint. Эти данные не отправляются
в репозиторий и не затираются обновлением программы.
app\versions — версии программы; app\current.json — текущий комплект.
server\world\checkpoint.json и .bak — состояние вашей серверной колонии.
Если основной checkpoint повреждён, сервер пробует резервную копию.
Чтобы начать новую колонию, останови игру и сервер, сделай копию server\world,
перемести эту папку за пределы server и выбери новый начальный ZIP.
Не публикуй локальную папку данных: она содержит пароль и колонию.

Проверки автоматизированы и выполняются перед публикацией релиза.
Полная игровая сессия на двух физических ПК через Radmin требует проверки
в вашей сети. Сервер сохраняет проверки десинков; полной гарантии их
отсутствия нет. При десинке нужны Player.log и MpDesyncs обоих игроков.
